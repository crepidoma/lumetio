# lumetio 設計書

日々の作業記録から、日報テキストと工数 CSV を作るデスクトップアプリ。

この文書が仕様の正。
決まりを変えるときは、この文書を先に直してから実装する。
「(仮)」と書いた値 (ペインの幅、畳む幅など) は、使いながら調整してよい。

---

## 1. 目的

1 日の終わりに、最小の手間で次の 3 つを済ませる。

1. 工数を付ける。プロジェクトごとの時間を出し、工数システムに CSV で取り込む。
2. 日報を送る。やったことや連絡をテキストにして貼り付ける。
3. 抱えている仕事を見失わない。

### 避けたいこと

| 避けたいこと | 扱い |
| --- | --- |
| 同じ仕事が何日も続くのに、毎日前の日の記録を写してくる | 「直近のタスク」から＋で足す (§5.2) |
| よく使う記録を、設定画面で事前に探したり登録したりする | よく使う、いつもの時間、繰り返しを、タスクの編集画面で使いながら設定する (§5.2, §5.3) |
| 日ごとの欄の定義を変えるのに、設定画面へ行く | メモ欄は日次画面で追加、名前変更、削除できる (§5.5) |
| 細切れの時間や、1:15 のような時間を入れにくい | 1 つのタスクに時間をいくつでも足せる。書き方を増やす (§6) |
| 工数の計算のために、出力のテンプレートが複雑になる | 「計上しない」と「時間不定」をアプリが扱う (§5.4) |

## 2. 前提

- 自分用。ただし作りは汎用にし、特定の会社や運用に寄せた概念は組み込まない。配布はしない (署名、インストーラ、多言語対応は扱わない)。UI は日本語のみ。
- Windows と macOS で動く。データフォルダを OneDrive などで共有して、複数の PC から使う。
- データは 1 日 1 ファイルのテキスト (YAML)。何も操作していない日のファイルは作らない。
- 日次ファイルは、それだけで完結させる。タスクや設定を後から変えても、過去の日は変わらない。
- 再生成で保証するのはデータの同一性まで。テンプレートを変えたら、過去の日を再生成した結果も変わる。過去の出力そのものは出力先に残っているものを正とする。
- AI からは、MCP サーバを通して外から操作させる。アプリの中では LLM を呼ばない。
- 画面に説明文、ヒント、注記を置かない。仕様の説明は文書に書く。

## 3. 技術構成

| 領域 | 採用 | 理由 |
| --- | --- | --- |
| デスクトップ | Wails (Go) | OS の WebView を使い、Chromium を同梱しない。Rust より大幅に軽いビルド |
| バックエンド | Go | ファイル I/O、ドメインロジック、出力、MCP をすべて Go に置き、GUI と MCP で同じ処理を使う |
| フロントエンド | React + TypeScript + Vite、パッケージ管理は pnpm | 画面だけを担当する |
| 画面の部品 | Mantine | 入力欄、ダイアログ、知らせ、カレンダー、ダークモードがそろっていて、自分で作る部品が少なくて済む |
| テンプレート | Go 標準の text/template | MCP からも出力を作るため Go 側で処理する |

- Wails は v3.1.0 (2026-11-01 の版)。Go、Node.js、pnpm の版は mise.toml で固定する。
- 依存と理由は次のとおり。足すときは理由を残す。
  - YAML: go.yaml.in/yaml/v3 (YAML の団体が保守する後継。v4 は正式版が出てから検討する)
  - ファイルの監視: fsnotify
  - Unicode の正規化: golang.org/x/text
  - Windows のドキュメントのフォルダ: golang.org/x/sys (OneDrive にリダイレクトされていても、OS から場所を取るため)
  - MCP: 公式の Go SDK
  - 画面のドラッグでの並べ替え: @dnd-kit (周りの行がよける動きとキーボードでの並べ替えを、自分で作らずに済むため)
  - 画面のテスト: Vitest と、その browser mode で使う Playwright と vitest-browser-react (画面の部品を、実際のブラウザの Chromium と WebKit で確かめるため)
- 画面の部品は Mantine を土台にし、自分で作ると手間のかかるもの (カレンダー、候補の一覧、ダイアログ、知らせ、入力欄) に使う。ヘッダー、ペイン、記録の行などの見た目は自前の CSS で書く。色は CSS 変数にまとめ、Mantine の部品も同じ色に合わせる。Mantine が求めるので、React は 19 にする。
- フォントは、当面は OS に入っているものを使う (アプリは外と通信しないので、Web フォントを読み込まない)。
- 日付は、Go と画面のあいだを `YYYY-MM-DD` の文字列で受け渡し、計算は Go で行う。画面に出す日付の文字は `Intl.DateTimeFormat` で作る。
- カレンダーには `@mantine/dates` を使う。これが求める dayjs は入れるが、dayjs の書式は書かない (日付の書式の記号は §6.2 にそろえたいため)。カレンダーの見出しなども、書式ではなく文字を返す関数で作る。

## 4. ファイル

### 4.1 データフォルダ

アプリが読み書きするデータを置く。ユーザーが普段開くことは想定しない。複数の PC で使うときは、OneDrive などの共有フォルダに移す。

```
<データフォルダ>/
  settings.yaml          プロジェクト、メモ欄の定義、長さの表記 (§4.4)
  items.yaml             タスクごとの設定 (よく使う、いつもの時間、繰り返しなど。§5.2)
  templates/             出力と出力セット。1 つにつき 1 ファイル (§7.1)
    日報テキスト.tmpl
    工数CSV.csv.yaml
    日報.set.yaml
  days/
    2026/
      2026-10-29.yaml    その日の記録
```

### 4.2 PC ごとのローカル設定と場所の初期値

ローカル設定は共有しない。PC ごとに違うもの、その PC の画面に合わせるものだけを持つ。

- データフォルダの場所
- 出力先の場所
- ペインの幅、ウィンドウの大きさと位置

| もの | 場所 | Windows の初期値 | macOS の初期値 |
| --- | --- | --- | --- |
| ローカル設定 | 固定 | `%APPDATA%\lumetio\local.yaml` | `~/Library/Application Support/lumetio/local.yaml` |
| データフォルダ | ローカル設定で変えられる | `%APPDATA%\lumetio\data\` | `~/Library/Application Support/lumetio/data/` |
| 出力先 | ローカル設定で変えられる | ドキュメントの下の `lumetio\` | `~/Documents/lumetio/` |

- ローカル設定とデータフォルダを別のフォルダにするのは、データフォルダを丸ごと共有フォルダへ移したときに、PC ごとの設定まで共有しないため。
- 出力先は、ユーザーが手に取るものなので、普段見る場所に置く。パスは PC ごとに違うので、共有する settings.yaml には置かない。
- Windows のドキュメントは OneDrive にリダイレクトされていることがあるので、決め打ちせず OS から取る。

```yaml
# local.yaml
data_dir: D:\OneDrive\lumetio
output_dir: D:\OneDrive\ドキュメント\日報
window:
  width: 1280
  height: 800
  x: 120
  y: 80
  maximized: false
panes:
  left: 260
  right: 380
  right_collapsed: false
```

- `data_dir` と `output_dir` は、書かれていなければ初期値を使う。相対パスは、どこを基準にするか分かりにくいのでエラーにする。
- 知らないキーはエラーにする。
- `window` は、閉じたときのウィンドウの大きさと位置、最大化していたか。最大化していたときは、最大化する前の大きさと位置を持つ。元に戻したときに、その大きさに戻れるようにするため。
- `panes` の `left` と `right` は左と右のペインの幅 (px)。割合でなく px にするのは、ペインの中身の読みやすさが幅の px で決まるため。ウィンドウを広げたときは中央が広がる。
- `panes` の `right_collapsed` は、右ペインを閉じるボタンで畳んでいるか。次に開いたときも畳んだままにする。ウィンドウが狭くて自動で畳んでいることは保存しない (ウィンドウの幅で決まるため)。
- `window` と `panes` の項目は任意。書かれていなければ初期値 (1280×800 で主の画面の中央、左 260、右 380) を使う。範囲の外の値はエラーにせず範囲に収める。手で書き換えたときに起動できなくなるのを避けるため。
- 前回の位置が、今つながっている画面のどれにも入らないとき (外付けの画面を外したときなど) は、主の画面の中央に開き、大きさもその画面に収める。
- アプリが `window` と `panes` を書くときは、一時ファイルを通して置き換える。`local.yaml` は PC ごとのファイルで、書くのはこのアプリだけなので、他で変わっていないかは確かめない。書き直すので、手で書いたコメントは残らない。
- 出力先のフォルダがなければ、書き出すときに作る。

### 4.3 共有で気をつけること

- 読み込むテキストはすべて Unicode NFC に正規化する (macOS と Windows の差を吸収する)。
- 他の PC で書き換えられたファイルは、監視して読み直す。
  - データフォルダの日次ファイル、settings.yaml、items.yaml、templates/ を、OS の変更の知らせ (fsnotify) で監視する。定期的に確かめることはしない。OneDrive などの同期フォルダは手元のファイルなので、知らせが来る。
  - 知らせは少しまとめてから画面に送る。日次ファイル、settings.yaml、items.yaml が変われば、開いている日 (左ペインの一覧を含む) を読み直す。どの日の記録も直近のタスクに効くので、ほかの日が変わったときも読み直す。templates/ か settings.yaml が変われば、右ペインの出力の一覧を読み直す。検索の候補は検索を始めるたびに作るので、次の検索から新しくなる。
  - このアプリ自身が書いたファイルの知らせは、画面に送らない。書く操作は、書いた後の日、使えるプロジェクト、左ペインの一覧をまとめて画面に返すので、読み直しは要らないため。書き始める前に他で変わっていた (その知らせを送る前に書いた) ときと、書いた後にさらに他で変わったときは、送る。
  - 読み直しても知らせは出さない。MCP が書いたときにも同じ知らせが来るので、出すと AI に頼むたびに出てしまうため。
  - 開いているダイアログ (設定画面、タスクの編集など) の中身は変えない。入力中の内容が勝手に変わらないようにするため。他の変更とぶつかれば、保存するときに今と同じく読み直して知らせる。
  - データフォルダがまだなければ、監視を始めるときに作る。
  - 監視を始められなくても、起動やデータフォルダの変更は止めない。他の変更が自動で画面に出ないだけで、保存するときの確かめは効くため。
- 保存の直前に更新日時を確かめる。読み込んだ後に他で変わっていたら上書きせず、読み直して知らせる。読み込んだときに無かったファイルが、保存の時点でできていた場合も同じ。
- 書き込みは同じフォルダの一時ファイルに書いてから置き換える。途中で止まっても、元のファイルを半端な中身にしない。
- 日次ファイルの中の日付がファイル名と違うときは、エラーにして開かない。
- settings.yaml、items.yaml も、日次ファイルと同じく、保存の前に更新日時を確かめ、一時ファイルを通して書く。出力と出力セットのファイルは、開いたときの中身と今の中身を比べて確かめる。どれも、知らないキーがあれば、エラーにして開かない。

### 4.4 settings.yaml

```yaml
projects:
  - code: DEV-001
    name: '[開発]サンプルアプリ'
    start: 2026-04-01
    until: 2026-12-31
  - code: ADMIN
notes:
  - name: 在宅
    type: bool
    carry_over: true
  - name: 連絡
duration_format: 'H:mm'
default_output: 日報
```

| キー | 中身 |
| --- | --- |
| `projects` | プロジェクトの一覧。プロジェクトを入力するときの候補 |
| `projects[].code` | コード。必須。一覧の中で重ならない |
| `projects[].name` | 名前。任意。なければコードを名前として使う |
| `projects[].start` | この日から使える。任意 |
| `projects[].until` | この日まで使える。任意。`start` より前の日はエラー |
| `notes` | メモ欄の定義。並びが画面の順 (§5.5) |
| `notes[].name` | 欄の名前。必須。一覧の中で重ならない |
| `notes[].type` | 値の型。`text` (省略時) か `bool` |
| `notes[].carry_over` | 前回の値を引き継ぐ。省略時 false |
| `duration_format` | 画面での長さの表記 (§6.1)。省略時 `H:mm` |
| `default_output` | 最初に選ばれている出力か出力セット (§7.1)。任意 |

- settings.yaml がなければ、すべて省略時の値で動く。設定を変えた時点でファイルを作る。
- 書き出すときのキーの順は表の順。
- 長さの表記は、使う人の好みなので PC ごとではなく共有する。

#### プロジェクトの期間

`start` から `until` までを、プロジェクトの期間と呼ぶ。開始前の日と、期限 (`until`) を過ぎた日は、期間の外とする。

- 期間は、今日ではなく、開いている日と比べる。期間の外の日には、プロジェクトの候補に出さない。期間の中の日を開いて直すときは候補に出る。
- すでに記録に付いているプロジェクトは、期間の外でもそのまま残す。
- 直近のタスク、よく使うタスク、定期的なタスクが期間の外のプロジェクトを持っていても、＋や実施済ではそのまま記録する。付け替えるかは記録した人が決める。
- その日の記録に期間の外のプロジェクトがあれば、警告する (日次画面は §8.1、出力は §7.4、MCP は §9)。
- 一覧にないプロジェクト (自由に入力したもの) は、期間がないので警告しない。

## 5. データと振る舞い

### 5.1 その日の記録 (`days/YYYY/YYYY-MM-DD.yaml`)

```yaml
date: 2026-10-29
tasks:
  - title: ログイン画面の改修
    project:
      code: DEV-001
      name: '[開発]サンプルアプリ'
    time: ['09:30-11:30']
  - title: 経費の精算
    project:
      code: ADMIN
      name: 事務作業
    time: [30m, 60m, '16:00-17:00']
  - title: 新しいライブラリの調査
    project:
      code: RESEARCH
    tags: [ふりかえり]
    note: |
      試作して、使えそうなことを確かめた。
  - title: 昼の勉強会
    project:
      code: STUDY
      name: 勉強会
    exclude: true
    time: ['12:00-13:00']
skipped: [週次ミーティング]
notes:
  在宅: true
  連絡: 15時から外出します
```

| キー | 中身 |
| --- | --- |
| `tasks[].title` | タスク名。必須。その日の中で重ならない |
| `tasks[].project` | プロジェクト。任意 |
| `tasks[].project.code` | プロジェクトのコード。`project` を書くなら必須 |
| `tasks[].project.name` | プロジェクトの名前。任意。なければコードを名前として使う |
| `tasks[].tags` | タグ。任意 |
| `tasks[].note` | タスクごとのメモ。任意 |
| `tasks[].exclude` | 工数に計上しない。省略時 false |
| `tasks[].done` | そのタスクはこの日で完了 (§5.2)。省略時 false |
| `tasks[].time` | 時間の並び。開始-終了 (`HH:MM-HH:MM`) と長さ (分。`Nm`) を混ぜてよい。空なら時間不定 |
| `skipped` | その日に「スキップ」した定期的なタスクの名前 |
| `notes` | メモ欄。欄の名前と値の組。値は文字列か `true`。空の欄は書かない (§5.5) |

- id、作成日時、定義の写しは持たない。
- タスクの情報 (プロジェクト、タグなど) は、記録した時点の値を写して持つ。
- メモ欄は名前で持つので、後で欄の名前を変えたり消したりしても、過去の日はそのまま開ける。過去の日に、今の定義にない欄があれば、それも表示する。
- 長さは、どの書き方で入力しても分 (`90m`) にそろえて保存する。開始-終了は `HH:MM-HH:MM` にそろえる。
- 書き出すときは、上の例の形にそろえる (キーの順は表の順。`project` は改行とインデントで書く。開始-終了は引用符で囲む)。手で書いたファイルは、引用符がなくても読める。
- 知らないキーがあるファイルは、エラーにして開かない。読み飛ばすと、保存し直したときに消えてしまうため。
- タスク名が重なっているファイルも、エラーにして開かない。
  予定や直近のタスクから、どちらの記録を指すのか決まらないため。

### 5.2 タスク

「タスク」は、何日も続く仕事の単位。会議や事務も含む。次の 2 つから組み立てる。

- **直近のタスク:** 開いている日までの 14 日 (その日を含む) の日次ファイルに出てくるタスク。最後に記録した日が新しい順に並べる。開いている日より後の記録は見ない。読めない日次ファイルは除いて計算し、計算とは別に知らせる。保存はせず、日を開いたときと日次ファイルの変更時に計算する。
- **items.yaml:** タスクの設定 (よく使う、いつもの時間、繰り返し) と、＋や実施済で使うプロジェクト、タグ、計上しないを持つ。items.yaml の 1 件は、それだけで完結する (過去の記録で穴を埋めない)。設定のないタスクは書かない。

```yaml
- title: 朝会
  project:
    code: MEETING
    name: 会議
  time: ['09:00-09:15']
  repeat:
    freq: weekly
    by_day: [mo, tu, we, th, fr]
- title: 週次ミーティング
  project:
    code: MEETING
    name: 会議
  time: ['13:00-14:00']
  repeat:
    freq: weekly
    by_day: [th]
- title: 月例報告会
  time: ['15:00-15:30']
  repeat:
    freq: monthly
    by_day: [2mo]
- title: 問い合わせ対応
  project:
    code: SUPPORT
    name: サポート
  time: [30m]
  favorite: true
```

| キー | 中身 |
| --- | --- |
| `title` | タスク名。必須。items.yaml の中で重ならない |
| `project` | プロジェクト。形は日次ファイルと同じ (§5.1)。任意 |
| `tags` | タグ。任意 |
| `exclude` | 工数に計上しない。省略時 false |
| `time` | いつもの時間。形は日次ファイルの `time` と同じで、複数書ける。任意 |
| `repeat` | 繰り返し (§5.3)。任意 |
| `favorite` | よく使うタスクに出す。省略時 false |

- 書き出すときのキーの順は表の順。知らないキーやタイトルの重なりは、エラーにして開かない。
- タスクを初めて items.yaml に書くとき (よく使う、いつもの時間、繰り返しのどれかを設定したとき) は、プロジェクト、タグ、計上しないを、開いている日までで一番新しい記録から写す。
- よく使うタスクと定期的なタスクを＋や実施済で記録するときは、items.yaml の値だけを使い、過去の記録は見ない。items.yaml で空の項目は空のまま。
- 直近のタスクを＋で記録するときは、プロジェクト、タグ、計上しないを、開いている日までで一番新しい記録から写す。そのタスクが items.yaml にもあれば、items.yaml の値を使う。時間とメモは、その日ごとのものなので写さない。
- 直近のタスクで、最後に記録した日が同じものは、その日の記録の並びの順に並べる。記録は並べ替えられるので (§8.1)、並べ替えた結果の順になる。追加した順は持たない。
- いつもの時間は、＋で足したときと、定期的なタスクの予定に、すべて入る。
- タスクのタイトルを変えたら、items.yaml のタイトルだけを書き換える。過去の記録は古いタイトルのまま残る。
- 設定をすべて外したタスクは、items.yaml から消す。

#### 完了

- 「完了」は、終わったタスクを直近のタスクからすぐに消す操作。何もしなければ、終わったタスクも 14 日間は一覧に残るため。
- 完了は、そのタスクを最後に記録した日の記録に `done: true` を付けて表す (§5.1)。items.yaml には持たない。
- タスクが最後に出てくる記録に `done: true` があれば、直近のタスクに出さない。後でまた記録すれば、最後の記録が新しい日に移るので、直近のタスクに戻る。
- 「完了」で今日でない日のファイルを書き換えることがある。その日でそのタスクが終わったという記録なので、その日に持つ。

左ペインのタスクの一覧は次の 3 区分にする。

| 区分 | 出るタスク | 消える条件 |
| --- | --- | --- |
| 直近のタスク | 開いている日までの 14 日に記録したタスク | 14 日記録しない、または完了にする |
| よく使うタスク | `favorite: true` のタスク | よく使うを外す |
| 定期的なタスク | `repeat` を持ち、開いている日が `start` から `until` の間にあるタスク。開いている日に予定が出るものを普通に出し、それ以外 (別の曜日など) は折りたたんだ領域に出す | 繰り返しを外す、`until` を過ぎる |

- `start` より前のタスク、`until` を過ぎたタスクは、左ペインに出さない。タスクの管理画面 (§8.3) にだけ出す。
- よく使うタスクは、items.yaml の並びの順に出す。並べ替えると items.yaml の並びも変わる。
- よく使うタスクを並べ替えたときは、よく使うタスクどうしの順だけを入れ替え、ほかのタスクの位置は変えない。よく使うタスクが入っていた位置に、新しい順で入れ直す。予定は items.yaml の順に出る (§5.3) ので、予定の並びまで変わらないようにするため。
- タスクの設定は、左ペインのタスクの一覧か、タスクの管理画面から行う (§8.1、§8.3)。中央の記録の行では、その日の記録だけを直す。
- 一覧にないタスクも、検索欄から過去のすべての記録と items.yaml を対象に探せる。
- 検索は部分一致で、大文字と小文字、全角と半角を区別しない (NFKC にそろえて比べる)。ひらがなとカタカナは区別する。
- 検索の結果は、最後に記録した日が新しい順に並べ、記録したことのない items.yaml のタスクはその後に並べる。出すのは 30 件まで (打ち始めは多く当たるので、見て選べる数に絞る)。
- 検索のたびにすべての日次ファイルを読むと、年数がたつと遅くなる。検索欄に入ったときにタスク名の一覧を 1 回作り、打つたびにその一覧から絞り込む。
- 検索の結果を選ぶと、＋と同じく開いている日の記録に足す。
- 検索欄に新しい名前を打てば、その場でタスクとして記録できる。登録の操作はない。
- ＋を押すと、開いている日の記録に足す。いつもの時間があれば、その時間で入る。
- その日にもう同じタスクの記録があれば、新しい行は作らず、その記録に時間を足す。
  プロジェクトなどは、すでにある記録の値のまま変えない。

### 5.3 定期的なタスク (繰り返し)

繰り返しの決まりは、iCalendar (RFC 5545) の繰り返し (RRULE) の語と意味に合わせる。キーは小文字のスネークケース、値は小文字で書く (RFC 5545 は名前と列挙値の大文字小文字を区別しない)。受け付けるのは、画面で作れる次の組み合わせだけにする。画面で開けない設定ができないようにするため。

| 画面の選択 | 書き方 |
| --- | --- |
| 毎日 | `freq: daily` |
| 平日 | `freq: weekly`、`by_day: [mo, tu, we, th, fr]` |
| 毎週 月・木 | `freq: weekly`、`by_day: [mo, th]` |
| 隔週 水 | `freq: weekly`、`interval: 2`、`by_day: [we]`、`start` |
| 毎月 第 2 月曜 | `freq: monthly`、`by_day: [2mo]` |
| 毎月 最終金曜 | `freq: monthly`、`by_day: [-1fr]` |
| 毎月 25 日 | `freq: monthly`、`by_month_day: [25]` |

| キー | RFC 5545 | 中身 |
| --- | --- | --- |
| `freq` | `FREQ` | `daily`、`weekly`、`monthly`。必須 |
| `interval` | `INTERVAL` | 間隔。省略時 1。`weekly` でだけ 2 を書ける |
| `by_day` | `BYDAY` | 曜日 (`mo`〜`su`)。`weekly` では 1 つ以上必須。`monthly` では週の番号 (`1`〜`5`、最終は `-1`) を前に付けて 1 つだけ |
| `by_month_day` | `BYMONTHDAY` | 日 (`1`〜`31`)。`monthly` でだけ 1 つ書ける |
| `start` | `DTSTART` | いつから。隔週では必須で、数え始めも兼ねる。ほかは任意 |
| `until` | `UNTIL` | いつまで (この日を含む)。任意 |

- `monthly` は、`by_day` と `by_month_day` のどちらか 1 つを書く。
- `until` が `start` より前のとき、`weekly` の `by_day` で同じ曜日を 2 回書いたときは、エラーにする。
- 表にない組み合わせ (`daily` に `by_day`、`interval: 3` など) はエラーにする。
- 週は月曜から始まる (RFC 5545 の `WKST` の既定)。隔週は、`start` を含む週から 1 週おき。
- その月にない日 (2 月 30 日、第 5 月曜がない月など) は、その月には出さない (RFC 5545 と同じ)。
- 定期的なタスクは、該当する日に「予定」として記録の一覧に並ぶ。予定の段階ではファイルに書かず、出力にも入れない。
- 予定は items.yaml の順に並べる。その日にもう同じタスクの記録があるとき、スキップしたときは出さない。
- 「実施済」で記録になる。「スキップ」で一覧から消え、`skipped` に書く。祝日や休みの日に出た予定も、「スキップ」で消す。
- 実際には別の日にあった会議は、その日に左の「定期的なタスク」から＋で足す。繰り返しの設定は変えない。
- 実施済にした後に時間を書き換えても、繰り返しの設定は変わらない。

### 5.4 工数の計算

- タスクの時間 = `time` の合計。開始-終了で終了が開始より前なら、日をまたいだとみなす。
- `time` が空のタスクは「時間不定」。合計には足さない。日報には載る。
- `exclude: true` のタスクは工数に計上しない。日報には載る。
- プロジェクトごとの合計 = 計上するタスクの時間の合計。時間不定のタスクが混ざっていれば、そのことも出力に渡す (テンプレートで「+α」と書ける)。「計上しない」の時間不定のタスクは、これに含めない。
- プロジェクトはコードでまとめ、最初に出てきた順に並べる。工数システムへの取り込みはコードで行うため。
- まとまりの名前は、そのコードで最初に出てきた記録の名前 (名前がなければコード)。名前が同じでもコードが違えば別のまとまりになる。
- プロジェクトのないタスクは、名前とコードが空の 1 つにまとめる。

### 5.5 メモ欄

- 日ごとの自由な欄 (在宅、連絡、ひとことなど)。定義は settings.yaml に置く (§4.4)。
- 日次画面の上で、欄の追加、名前の変更、削除、並べ替えができる。
- 欄の名前を変えても、消しても、日次ファイルはどの日も書き換えない。過去の日を書いたときのまま開けるようにするため。前の名前の値は、定義のない欄として出る。引き継ぐ欄は、新しい名前では前回の値がないので、名前を変えた次の日は空から始まる。
- 欄の型は、テキスト (`text`) と真偽値 (`bool`)。
- 空は、テキストなら空文字、真偽値なら false。日次ファイルには空でない欄だけを書き、空の欄は書かない。書いていない欄と空の欄は同じ意味なので、空を書いても何も伝わらず、欄の名前を変えたときに中身のない欄がどの日にも残るだけなため。欄を空にしたら (文字を消す、スイッチを切る)、その欄をファイルから消す。手で書いたファイルにある空の値は、書いていないものとして読む。
- 欄ごとに「毎回空」か「前回の値を引き継ぐ」(`carry_over`) を選べる。引き継ぐ場合、「前回」は、その日より前で日次ファイルがある一番近い日の値。その日のファイルにその欄がなければ、空を引き継ぐ。
- 日次ファイルを作るとき (§5.6) は、引き継ぐ欄のうち、前回の値が空でないものを書く。メモ欄に触らなかった日も、引き継ぎが途切れないようにし、後から定義を変えても過去の日が変わらないようにするため。
- ファイルのある日は、ファイルの値をそのまま出す。定義にあってファイルにない欄は空で出し、前回の値は引き継がない。その日のファイルが正なので。
- 引き継ぐ値の型が今の定義と違うとき (定義を後から変えたときなど) は、引き継がずに空にする。ファイルにある値は、型が違ってもそのまま出す。
- 過去の日に、今の定義にない欄があれば、定義にある欄の後ろに、ファイルに書かれた順で出す。空の値は書いていないものとして扱うので、出さない。
- 前回の日のファイルが読めないときは、さらに前の日を探す。読めなかったファイルは、計算とは別に知らせる。
- 日次ファイルの値の形は、型ごとに決める。定義を消した後でも、過去の日は値の形から読めるようにするため。

| 型 | 日次ファイルの値 |
| --- | --- |
| `text` | 文字列。空文字は書かない |
| `bool` | `true`。false は書かない (手で書いた `false` は読める) |

- 選択肢から選ぶ欄 (1 つ、または複数) を足せる余地を残す。足すときは、`type: choice` に選択肢 (`options`) と複数選択 (`multiple`) を持たせ、日次ファイルの値は 1 つなら文字列、複数なら並びにする。

### 5.6 ファイルを作るタイミング

- 日を開いただけでは、ファイルを作らない。予定が表示されていても同じ。
- 次のどれかをした時点で作る: タスクを足す、時間を足す、予定を実施済にする、予定をスキップする、メモ欄を書く。
- 「スキップ」だけを押した日もファイルを作る (操作したことになるため)。

## 6. 時間の書き方

1 つの入力欄に、空白、カンマ、読点で区切って複数書ける。全角の数字、「：」、「～」も受け付ける。入力中に解釈結果を表示し、Enter で確定する。

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `H:MM-H:MM` | 開始から終了まで | `17:00-18:00` |
| `-H:MM` | 直前の記録の終わりから | `-12:00` |
| `H:MM-` | その時刻から今まで | `13:00-` |
| コロンなしの時刻 | `-` でつないだときだけ時刻と読む。1〜2 桁は時、3〜4 桁は下 2 桁が分 | `9-10`、`930-1130`、`-12` |
| 整数 | 分 | `75` = 1:15 |
| 小数 | 時間。分未満は四捨五入 | `1.5` = 1:30、`.5` = 0:30 |
| `H:MM` (単独) | 長さ | `1:15` |
| `Nh`、`Nm`、`NhNm` | 長さ | `1h15m`、`30m`、`1.5h` |

- 時刻は分の入力の代わり。同じ時間帯に重なる記録があってもよい。
- 終了が開始より前なら日をまたいだとみなす (`23-5` は 6 時間)。`24:00`〜`47:59` も翌日の時刻として受け付け、24 時間を引いて保存する (`29:00` は `05:00`)。
- ハイフンの後ろに空白があるときは、前後の空白を無視する (`9 - 10` は `9-10`)。`16:30 -17:00` のように後ろに空白がないときは、`-17:00` を別の時間として読む。
- 「直前の記録」は、その日の全タスクの記録 (予定は含まない) の開始-終了のうち、指定した終了時刻以前に終わっている一番遅いもの。同じ入力の中で先に書いた時間も含む。なければエラー。ちょうど指定した時刻に終わる記録があれば、開始と終了が同じになるのでエラー。
- 「今まで」は今日だけで使える。今日以外の日や、今がまだその時刻より前なら、エラー。
- 開始と終了が同じ、0 分、24 時間を超える長さはエラー。
- 記録済みの時間 (チップ) はクリックで編集できる。書き方は入力と同じ。
- 画面での長さの表記は、settings.yaml の `duration_format` で書式として決める。保存形式 (分) と出力 (テンプレートの `time` は `H:mm`) には影響しない。

### 6.1 長さの書式

UTS#35 の日時の書式 (`HH:mm` など) と同じ記号を使う。テンプレートの `duration` 関数 (§7.2) も同じ書式を使う。

| 記号 | 意味 |
| --- | --- |
| `H`、`HH` | 時間。`HH` は 2 桁にそろえる |
| `m`、`mm` | 分。`mm` は 2 桁にそろえる |
| `'…'` | 文字をそのまま出す。`''` で `'` を出す |

- 書式にない大きい単位の分は、小さい単位に入る。`H` がなければ、分に時間の分も入る (Apache Commons の `DurationFormatUtils` と同じ作法)。
- 書式の中でいちばん小さい単位は、余りを小数で出す。小数は最大 2 桁で四捨五入し、末尾の 0 は書かない。
- 日付の書式 (§6.2) と同じく、`a`〜`z` と `A`〜`Z` は記号のために取っておく。`H` と `m` 以外の英字、`HHH` のような 3 文字以上の並び、`H` も `m` もない書式はエラーにする。英字以外 (`:`、`.`、日本語など) はそのまま出す (`H時間m分` と書ける)。

| 書式 | 90 分 | 75 分 | 50 分 |
| --- | --- | --- | --- |
| `H:mm` (既定) | `1:30` | `1:15` | `0:50` |
| `m'm'` | `90m` | `75m` | `50m` |
| `H'h'm'm'` | `1h30m` | `1h15m` | `0h50m` |
| `H'h'` | `1.5h` | `1.25h` | `0.83h` |

### 6.2 日付の書式

出力のファイル名 (§7.2)、テンプレートの `date` 関数、CSV からプロジェクトを取り込むときの日付の読み取り (§8.4) で使う。
記号は UTS#35 の日時の書式から、日付に使うものだけを選んだ。

| 記号 | 意味 | 2026 年 3 月 9 日 |
| --- | --- | --- |
| `yyyy`、`yy` | 年。`yy` は下 2 桁 | `2026`、`26` |
| `MM`、`M` | 月。`MM` は 2 桁にそろえる | `03`、`3` |
| `dd`、`d` | 日。`dd` は 2 桁にそろえる | `09`、`9` |
| `EEE`、`EEEE` | 曜日 | `月`、`月曜日` |
| `'…'` | 文字をそのまま出す。`''` で `'` を出す | |

- `a`〜`z` と `A`〜`Z` は記号のために取っておく。表にない英字や並び (`HH`、`yyy` など) はエラーにする。英字以外 (`/`、`-`、日本語など) はそのまま出す。
- 時刻 (`HH`、`mm` など) は使えない。日次ファイルは時刻を持たないため。

## 7. 出力

### 7.1 出力と出力セット

- 出力と出力セットは、データフォルダの `templates/` に 1 つにつき 1 ファイルで、フォルダを切らずに置く。自由に増やせる。
- 出力の種類はテキスト (テンプレート) と CSV の 2 つ。
- 出力セットは、いくつかの出力をまとめて一度に作るための組み合わせ。
- 種類はファイル名で分ける。名前は、ファイル名から種類と拡張子を除いた部分。

| ファイル名 | 種類 | 名前 |
| --- | --- | --- |
| `日報テキスト.tmpl` | テキストの出力 (§7.2) | 日報テキスト |
| `工数CSV.csv.yaml` | CSV の出力 (§7.3) | 工数CSV |
| `日報.set.yaml` | 出力セット | 日報 |

- YAML のファイルは、種類を `kind` に持つ (`csv`、`set`)。`kind` は必須で、ファイル名の種類と違うとき、知らない種類のときはエラーにする。種類を後から増やす余地を残すため。
- 名前は、出力と出力セットを通して `templates/` の中で重ならない。名前は NFC にそろえて比べる (macOS と Windows で濁点などの表現が違うため)。重なったら、その名前のファイルはどれも読めないものとして扱う。出力セットがどれを指すのか決まらないため。
- 読めないファイル (書き方の誤り、名前の重なりなど) は除いて、理由を別に知らせる。1 つのファイルの誤りで、ほかの出力まで使えなくならないようにするため。
- `templates/` にあって、名前の形 (`*.tmpl`、`*.csv.yaml`、`*.set.yaml`) に合わないファイルは無視する。

```yaml
# 日報.set.yaml
kind: set
outputs: [日報テキスト, 工数CSV]
```

- `outputs` は出力の名前の並びで、1 つ以上。並びが画面のタブの順。同じ名前を 2 回書いたとき、空の名前を書いたときはエラーにする。
- 存在しない出力や読めない出力を指していたら、その出力セットを使うときにエラーにする。

### 7.2 テキストの出力 (`*.tmpl`)

```
---
file: "'report_'yyyyMMdd"
extension: txt
encoding: utf-8
newline: lf
---
{{date "yyyy/MM/dd(EEE)"}} の日報

■ やったこと
{{- range .projects}}
- {{.name}}{{if .counted}} ({{.time}}{{if .has_untimed}} +α{{end}}){{end}}
{{- range .tasks}}
  - {{.title}}{{if .counted}} ({{.time}}){{end}}
{{- end}}
{{- end}}

■ 連絡
{{or .notes.連絡 "なし"}}
{{- with where .tasks "tags" "ふりかえり"}}

■ ふりかえり
{{- range .}}
- {{.title}}: {{.note}}
{{- end}}
{{- end}}
```

- 先頭の `---` で囲んだ部分 (必須) に、出力の設定を YAML で書く。知らない項目はエラーにする。

| 項目 | 中身 |
| --- | --- |
| `file` | ファイル名の書式 (§6.2)。必須 |
| `extension` | ファイル名の拡張子。必須。先頭に `.` を付けない |

- `file` と `extension` には、ファイル名に使えない文字 (`/\:*?"<>|`) を入れられない。
| `encoding` | `utf-8` (省略時) か `utf-8-bom` |
| `newline` | `lf` (省略時) か `crlf` |

- 本文は Go の `text/template` の書き方そのままで、独自の決まりを足さない。
  空白と改行は、Go と同じく `{{-` と `-}}` で詰める。
- テンプレートの誤り (書き間違えた値の名前、知らない関数など) はエラーにして、出力しない。

テンプレートに渡す値の名前は、YAML のキーと同じく小文字の snake_case にする。

| 値 | 中身 |
| --- | --- |
| `.date` | 日付。`2026-03-09` の形 |
| `.tasks` | 記録したタスク (予定は含まない)。記録の順 |
| `.projects` | プロジェクトごとのまとまり。そのプロジェクトが最初に出てくる記録の順 |
| `.total_minutes`、`.total_time` | 計上する時間の合計 (§5.4) |
| `.notes` | メモ欄 (§5.5)。`.notes.連絡` のように欄の名前で参照する。名前に空白や記号があるとき、名前が数字で始まるときは `{{index .notes "名前"}}` |

`.tasks` の各要素:

| 値 | 中身 |
| --- | --- |
| `title`、`tags`、`note`、`exclude` | 記録の値 |
| `project` | `code` と `name`。`name` がなければ `code` と同じ |
| `minutes`、`time` | 時間。`minutes` は分、`time` は `H:mm` で書いたもの。ほかの書式は `duration` で出す |
| `untimed` | 時間不定 |
| `counted` | 計上して、時間もある |

`.projects` の各要素:

| 値 | 中身 |
| --- | --- |
| `code`、`name` | プロジェクト。`name` は最初の記録のもの。なければ `code` と同じ |
| `minutes`、`time` | 計上する時間の合計。書き方は `.tasks` と同じ |
| `counted` | 計上する時間がある |
| `has_untimed` | 計上する時間不定の記録がある |
| `tasks` | そのプロジェクトの記録。要素は `.tasks` と同じ |

Go のテンプレートのアクション (`if`、`range`、`with` など) と組み込みの関数 (`len`、`index`、`eq`、`or`、`not` など) に加えて、次の関数を使える。

| 関数 | 中身 | 例 |
| --- | --- | --- |
| `date` | その日の日付を書式で出す。書式は §6.2 | `{{date "yyyy/MM/dd(EEE)"}}` |
| `duration` | 分を書式で出す。書式は §6.1 | `{{duration .total_minutes "H'h'"}}` |
| `where` | 一覧から、項目が値に合う要素を残す。項目の値が一覧なら値を含むもの、それ以外は値が等しいもの。項目は `project.code` のように `.` でたどれる | `{{range where .tasks "project.code" "DEV-001"}}` |
| `has` | 文字列の一覧が値を含むか | `{{if has .tags "ふりかえり"}}` |
| `join` | 文字列の一覧を区切り文字でつなぐ | `{{join .tags ", "}}` |

使い方の例は、[テンプレートリファレンス](template-reference.md) にまとめる。

### 7.3 CSV の出力 (`*.csv.yaml`)

```yaml
kind: csv
file: "'report_'yyyyMMdd"
encoding: utf-8
newline: crlf
header: true
rows: projects          # projects / tasks
skip_rows_without_counted: true
columns:
  - header: date
    value: '{{date "yyyy/MM/dd"}}'
  - header: code
    value: '{{.code}}'
  - header: hours
    value: '{{if .has_untimed}}-{{else}}{{duration .minutes "H"}}{{end}}'
```

知らない項目はエラーにする。

| 項目 | 中身 |
| --- | --- |
| `kind` | `csv`。必須 |
| `file`、`encoding` | §7.2 と同じ |
| `newline` | `crlf` (省略時) か `lf`。CSV の標準 (RFC 4180) に合わせて `crlf` を省略時の値にする |
| `header` | 見出しの行を出すか。省略時 `true` |
| `rows` | 行の単位。`projects` (プロジェクト) か `tasks` (タスク)。必須 |
| `skip_rows_without_counted` | `counted` でない行を出さない。省略時 `false` |
| `columns` | 列の並び。1 つ以上。各列は `header` (見出し) と `value` (値。必須) を持つ |

- 拡張子は `csv`、区切り文字はカンマに決まっている。CSV のほかの形 (タブ区切りなど) は、テキストの出力で書く。
- 各列の値は小さなテンプレートで書く。書き方と関数は §7.2 と同じ。クォートとエスケープはアプリがする。
- 行の単位 (`rows`) がプロジェクトなら `.projects` の各要素、タスクなら `.tasks` の各要素が渡る。

### 7.4 画面での出力

- 右ペインに、選んでいる出力セットの出力をタブで並べ、プレビューを表示する。編集のたびにすぐ変わる。出力が 1 つのときは、タブを出さない。
- 選ぶ欄には、出力セットのあとに、出力 1 つずつも並べる。出力セットを作らなくても、出力 1 つなら出せるようにするため。
- 起動したときは `default_output` を選ぶ。なければ一覧の先頭を選ぶ。選び直しても保存しない (既定は設定画面で変える)。
- プレビューは出力ごとに作り、作れない出力のタブにだけ誤りを出す。ほかの出力は見られるようにするため。
- 「コピー」で表示中の出力をクリップボードへ、「出力」で選んでいる出力セットのすべてを出力先に書く。コピーしたら、短く知らせる。
- 予定 (まだ実施済にしていないもの) は出力に入らない。
- その日の記録に期間の外のプロジェクト (§4.4) があれば、「コピー」と「出力」の前にダイアログで警告し、続けるかやめるかを選ばせる。アプリの外へ出す操作だけが対象で、プレビューでは出さない (編集のたびに出ると邪魔になるため)。
- 出力先に同じ名前のファイルがあるときは、上書き、別名で保存、キャンセルから選ぶ。
  確認は出力セットで 1 回にまとめ、すでにあるファイルを並べる。選んだ扱いは、すでにあったファイルのすべてに当てはめる (別名を選んでも、重ならないファイルは元の名前で書く)。
- 別名は、拡張子の前に、出力した時刻を `_yyyyMMddHHmmss` の形で付ける (`report_20260309_20261102153012.txt`)。
- セットの中に、同じファイル名になる出力が 2 つあれば、何も書かずにエラーにする。大文字と小文字だけが違う名前も同じとみなす (Windows と macOS では同じファイルになるため)。プレビューではエラーにしない。
- セットの出力をすべて作ってから書く。テンプレートの誤りなどで 1 つでも作れなければ、1 つも書かない。
  書き込みの途中で失敗したときは、どこまで書けたかを知らせる。
- 出力したら、書いたファイルの名前を知らせ、それぞれを OS の標準のアプリで開く。書いた結果をすぐ確かめ、貼り付けや取り込みに使えるようにするため。

## 8. 画面

### 8.1 日次画面

3 ペイン構成。ウィンドウ全体はスクロールせず、ペインごとにスクロールする。

```
┌ ヘッダー: ◀ 日付 ▶ 今日 | 検索・追加 | 設定 ─────────────────────┐
│ 左: タスク一覧┃ 中央: その日の記録           ┃ 右: メモ欄と出力   │
│ よく使うタスク┃ 合計                          ┃ メモ欄             │
│ 直近のタスク  ┃ 記録の一覧 (予定は点線)      ┃ 出力セット ▼       │
│ 定期的なタスク┃                               ┃ [日報][工数CSV]    │
│               ┃                               ┃ プレビュー         │
│               ┃                               ┃ [コピー][出力]     │
└───────────────┴───────────────────────────────┴────────────────────┘
```

- ペインの境目はドラッグで幅を変えられる。境目には Tab で移れ、左右キーで 16px ずつ動かせる。幅はローカル設定に保存する (§4.2)。
- 幅を保存するのは、ドラッグを離したときと、左右キーで動かして 0.5 秒たったとき。動かしている途中には書かない。ウィンドウの大きさと位置は、閉じるときに保存する。
- 幅の範囲 (仮): 左 200〜480px、右 280〜640px。中央は残りで、400px (仮) より狭くしない。足りなくなったら左を縮め、それでも足りなければ右を畳む。
- ウィンドウの最小の大きさ (仮) は 720×520px。左の最小、中央の最小、畳んだ右のバーが並ぶ幅と、記録の行が 3 つほど見える高さ。
- 右ペインは畳める。開閉のボタンは、開け閉めする右の領域そのものの最上段に置く。並べて開いた右ペインは最上段に閉じるボタンだけを置き、畳んだバーは最上段に開くボタンを置いて、同じ高さにそろえる。メモ欄や出力の並びを崩さずに、開け閉めの場所を変えないため。
- 畳むと細いバーになり、下にコピーと出力のボタンと出力セット名を置く。畳む条件は次のとおり。
  - 閉じるボタンを押したとき
  - ウィンドウ幅が 1100px 未満 (仮) か、右ペインを置くと中央が最小の幅より狭くなるとき (自動で畳む)
- 境目のドラッグや左右キーでは畳まない。幅は範囲の端で止まる。畳むかどうかを操作の勢いで決めず、ボタンで選ばせるため。
- 畳んでも右ペインの幅は覚えておき、開くと元の幅に戻る。
- 手で畳んだことは覚えておき (§4.2)、ウィンドウの幅が 1100px をまたいでも、起動し直しても畳んだままにする。開くボタンで元の場所に開く。手で開け閉めしたら、すぐ保存する。
- 並べて開け閉めするときは、右の領域の幅をなめらかに変え、右ペインとバーを重ねて薄くしながら入れ替える。境目をドラッグしているあいだは、幅が指に遅れないよう、なめらかに変えない。OS で「アニメーションを減らす」にしているときは動かさない。
- 自動で畳んでいるときは、右ペインをバーから左へ引き出し、中央を押し縮めずにその上に重ねる。中央を押し縮めると、中央が読めない幅になるため。
  - バーは右端に残り、その最上段のボタンで開け閉めする (« と » が入れ替わる)。引き出しているあいだは、バーのコピーと出力は隠す (右ペインに同じボタンがあるため)。引き出した右ペインには閉じるボタンを置かない。
  - 暗い幕は掛けず、ヘッダーや左ペインはそのまま使える。
  - 幅は中央を押し縮めないので広めの 560px (仮) にし、ウィンドウが狭いときは左端に 80px を残す。
  - 右ペインとバーの外 (中央、左ペイン、ヘッダー) を押すと、その操作をしつつ閉じる。右ペインから開いた候補の一覧、ダイアログ、知らせは外に数えない。バーのボタンか Esc でも閉じる。Esc は、確認のダイアログや開いている候補の一覧があれば、そちらだけを閉じる。
  - ＋や検索で足した記録の時間の欄に移るときも閉じる。重ねた右ペインの下に隠れた欄に打たないようにするため。
  - 閉じるときは、どの閉じ方でも同じようにフェードする。
  - 引き出すとき、しまうときは、バーのコピーと出力が、右ペインの下のコピーと出力の位置と大きさへ移っていく (しまうときは戻る)。別々のボタンが消えて現れるのではなく、同じボタンが動いて見えるようにするため。OS で「アニメーションを減らす」にしているときは動かさない。
  - 引き出したことは保存しない。
- 畳んでも開いても、選んでいる出力と表示中のタブは変えない。畳んだバーの「コピー」は、表示中のタブの出力を写す。
- 各ペインは、最小幅でも見た目が崩れないようにする。特に、右ペインが畳まれる直前の幅で崩れやすい。
- 左ペインのタスクの行には、タスク名、プロジェクトの名前、＋を出す。よく使うタスクへの出し入れ (☆) は、マウスを乗せたときだけ出す。
- よく使うタスクと定期的なタスクの行をクリックすると、タスクの編集 (§8.2) を開く。直近のタスクの行は、クリックしても開かない。直近のタスクに設定を付けたいときは、☆でよく使うタスクにしてから開く。
- 直近のタスクの行には、マウスを乗せたときだけ ✓ (完了) を出す。押すと、開いている日までで、そのタスクを最後に記録した日の記録に `done: true` を付ける (§5.2)。その日より後に記録があれば、§5.2 のとおり完了として扱われない。終わった日に記録を付けていないときなどに、最後の記録の日を開かずに消せるようにするため。
- 直近のタスクには、よく使うタスクと、開いている日に予定の出る定期的なタスクにあるものを出さない。同じタスクが 2 か所に並ばないようにするため。
- 開いている日にもう記録があるタスクは、左ペインの行に「記録あり」と出す。＋はそのまま使える (§5.2 のとおり時間を足す)。
- ＋や検索で記録を足したら、その記録の時間を足す欄に移る。いつもの時間がないタスクでも、続けて時間を打てるようにするため。
- よく使うタスクに入れるとき、そのタスクがまだ items.yaml になければ、§5.2 のとおり一番新しい記録から写して書く。外して設定が何も残らなければ、items.yaml から消す。
- 左ペインの最下段に、タスクの管理画面 (§8.3) を開く、アイコン付きのボタンを置く。タスクの一覧の近くで開けるようにするため。タスクの一覧をスクロールしても動かさない。
- よく使うタスクと、その日の記録は、ドラッグで並べ替えられる。見た目だけでなく、items.yaml と日次ファイルの並びも変わる。
  - 行の左端に、マウスを乗せたときと Tab で移ったときだけ出る取っ手を置き、そこをつかんで動かす。行のほかの場所 (タスク名、時間の欄など) の操作とぶつからないようにするため。
  - 動かす向きは縦だけで、一覧の外には出ない。つかんだ行の周りの行は、よけるように動く。
  - 置き場所は、マウスのいる位置の行で決める (キーボードのときは行の真ん中どうしで決める)。
  - 記録を動かし始めたとき、つかんだ行の詳しい表示が開いていたら、高さをなめらかに変えて畳む。背の高い行のままだと、動かしにくく、置き場所も見えにくいため。ほかの行は畳まない (つかんだ行より上の行が縮むと、つかんだ行がカーソルから上へずれるため)。
  - 記録の行の取っ手は、いちばん上の段 (タスク名の行) の高さに置く。畳むと行は下から縮むので、つかんでいる取っ手がカーソルの位置に残るようにするため。
  - キーボードでも並べ替えられる (取っ手で Space を押してつかみ、上下キーで動かし、Space で置く。Esc でやめる)。
  - 予定の行は動かさない。予定は items.yaml の順に出るもので、記録になっていないため。記録は、記録どうしで並べ替える。
  - 保存するとき、日次ファイルや items.yaml が他で変わっていれば、ほかの書き込みと同じく保存せず、読み直して知らせる (§4.3)。
- ヘッダーの日付を押すとカレンダーを開き、選んだ日に移る。今日を開いているときは「今日」を押せない。起動したまま日付が変わったら、「今日」は新しい日を指す。開いている日は自動では移さない。
- 予定の行には、「予定」の札、プロジェクトの名前、いつもの時間のチップを出す。
- 予定の行には、「実施済」を色の付いた主のボタンとして先に置き、「スキップ」を枠だけのボタンで後ろに置く。押すことが多いほうを目立たせるため。
- 記録の一覧の上に、その日の合計を出す。
- メモ欄は右ペインの上部に置く。多くは日報に載せる材料なので、書いた結果をすぐ下のプレビューで見られるようにするため。型によらず、左に名前、右に値 (真偽値はスイッチ) を並べる。
- メモ欄の見出しの横に鉛筆のボタンを置き、メモ欄の定義を直すダイアログを開く。中身は設定画面の「メモ欄」と同じ。保存したらダイアログを閉じる。欄が 1 つもないときも、見出しとボタンは出す。
- テキストのメモ欄は、欄を離れたときに書く。打ち始めた後に他で同じ欄が書き換わっていたら、書かずに読み直して知らせる (§4.3)。他の PC の書き換えを上書きしないため。他で書き換わった値が監視で届いたときも、欄は届いた値に入れ替える。
- メモ欄の高さは右ペインの 4 割 (仮) までにし、超えたらメモ欄の中でスクロールする。プレビューの場所を残すため。
- 右ペインを畳んでいるときは、メモ欄も開くボタンで右ペインを開いて書く。中央にも出すと、同じ欄が 2 か所に並ぶため。
- 画面は、よく使う操作を簡潔に出し、たまにしか使わない操作は隠す。隠した操作にも、決まった場所からたどり着けるようにする。
- 記録の行は、ふだんは簡潔な表示にする。タスク名、合計 (時間不定なら「不定」)、時間のチップ (クリックで編集、× で消す)、時間を足す欄を出す。
  チップの編集は Enter で書き、空にして Enter で消す。欄を離れたときは、書かずに編集をやめる。プロジェクト、タグ、計上しない、完了、メモは、値があるときだけ文字や札で出し、入力欄にしない。期間の外のプロジェクト (§4.4) は警告の色で出す。
- タスク名は、ふだんの表示で押すと、その場で直せる。
- 記録の行のタスク名、チップ、時間の欄以外を押すと、その行に詳しい表示を開く。プロジェクト、タグ、計上しない、完了、メモを直す欄と、記録を消す操作を置く。記録を消すときは、時間やメモごと消えて元に戻せないので、確かめてから消す。開くのは 1 行だけで、もう一度押すか Esc で閉じる。開け閉めは、高さをなめらかに変える。
- 記録の詳しい表示の「完了」は、その日の記録の `done` を付け外しする。その日でそのタスクが終わったという記録なので、その日の行で付ける。その日より後に同じタスクの記録があれば、印が効かないので、MCP と同じくエラーにして最後に記録した日を出す。
- 記録のメモとテキストのメモ欄は複数行で書ける。6 行 (仮) を超えたら、欄の中でスクロールする。
- 記録の行でタスク名を直すのは、打ち間違いを直すため。その日の記録の名前だけを変え、items.yaml は変えない。その日にもう同じ名前の記録があれば、エラーにする。
- 過去の日の表示は、その日のファイルだけを使う。
- 文字を打つ欄 (タスク名、時間、メモ欄など) の入力の誤りは、入力欄の枠を赤くし、入力欄の下に重ねた吹き出しで出す。周りの行を動かさないため。吹き出しは、誤りがなくなったときか Esc で消える。書こうとしたときに出た誤りは、打ち直したら消す (直した値にも誤りがあるように見えないため)。検索の誤りは、候補の一覧の見出しに出す。
- 選ぶ、押すなどで書く操作 (記録の詳しい表示の欄、タスクの編集の保存、左ペインの＋など) の誤りは、画面の端の知らせで出す。誤りを出しておく入力欄がないため。
- 衝突 (§4.3) で読み直したときと、ファイルの読み書きに失敗したときは、画面の端に知らせを出す。衝突の知らせは数秒で消え、読み書きの失敗は消すまで残す。
- 操作の前に確かめるダイアログ (破棄、削除、上書きなど) は、右下に「キャンセル」と続ける操作を並べる。やめるボタンの名前は、どのダイアログでも「キャンセル」にそろえる。問いかけは見出しにせず本文と同じ大きさの文で出し、右上の閉じるボタンは置かない (やめる操作は「キャンセル」にある)。
- ダイアログの上にダイアログを開くとき (設定画面の中の確かめるダイアログ、CSV からの取り込みなど) は、下のダイアログも暗くして見せたまま、上に重ねる。何の上で操作しているかが分かるようにするため。下のダイアログは、上のダイアログを閉じるまで操作できない。Esc は一番上のダイアログだけを閉じる。
- 明るい色と暗い色は、OS の設定に合わせる。
- 検索・追加の欄へは、Ctrl+K (macOS では ⌘K) で移る。欄の中にそのキーを出しておく (画面に説明を置かない決まりの例外。キーは見せないと気づけないため)。
- 検索の候補の先頭には、打った名前を新しいタスクとして足す行を出す。候補の行には、最後に記録した日を出す。Esc で、打った文字を消して欄を離れる。

### 8.2 タスクの編集

タイトル、プロジェクト (一覧から検索。期間の外のものは出さない。一覧にない値も入力可)、タグ、計上しない、いつもの時間、繰り返し、期間、よく使うタスクへの出し入れ、を 1 つのダイアログで扱う。変更は今後の記録にだけ効く。

- 編集するのは items.yaml にあるタスクだけ。左ペインのよく使うタスクと定期的なタスク、検索結果、タスクの管理画面から開く。中央の記録の行からは開かない (行で直すのはその日の記録だけ)。
- 検索結果からは、items.yaml にあるタスクの行にマウスを乗せたときだけ出る鉛筆のボタンで開く。行を選ぶ操作は、記録に足すことに使っているため。
- よく使うタスクへの出し入れは、タイトルの欄の右の☆で行う。左ペインの☆と同じ見た目にする。
- 変更は「保存」でまとめて書く。キャンセルや Esc では書かない。繰り返しの頻度、曜日、いつからは互いに関係するので、1 つ変えるたびに書くと、途中の組み合わせで誤りになるため。
- 開いているあいだに、他でそのタスクが変わったり消されたりしていたら、保存せずに読み直して知らせ、ダイアログを閉じる (§4.3)。開いたときの値で書くと、他の変更を上書きしてしまうため。
- タイトルを、items.yaml のほかのタスクと同じ名前にしたら、エラーにする。
- いつもの時間の書き方は、記録の時間と同じ (§6)。ただし、`-H:MM` (直前の記録の終わりから) と `H:MM-` (今まで) は、その日の記録と今の時刻を使うので、エラーにする。
- 繰り返しの選択肢は、なし、毎日、平日、毎週、隔週、毎月 (第 n 曜日、n 日)。期間は「いつから」と「いつまで」(§5.3 の `start` と `until`)。
- 隔週を選んだとき、「いつから」が空なら、開いている日を入れる。
- 完了はダイアログに置かない。完了は直近のタスクから消す操作で、よく使うタスクと定期的なタスクは直近のタスクに出ないため。完了は、直近のタスクの行と、中央の記録の行で付ける (§8.1)。

### 8.3 タスクの管理

- 左ペインの最下段のボタンから、大きなダイアログで開く。
- items.yaml のすべてのタスクを一覧にする。よく使うタスク、定期的なタスク (`start` より前のもの、`until` を過ぎたものを含む)、いつもの時間だけを持つタスクが対象。
- 一覧は items.yaml の順に並べ、タスク名、プロジェクトの名前、設定 (よく使う、いつもの時間、繰り返し) を出す。
- タスクを新しく作れる。記録したことのないタスクでも、よく使うタスクや定期的なタスクにできる。プロジェクトなどを写す元の記録がないので、空から入力する。
  タイトルと、設定 (よく使う、いつもの時間、繰り返しのどれか) がそろうまで保存できない。設定のないタスクは items.yaml に置かないため (§5.2)。
- 一覧からタスクの編集 (§8.2) を開ける。設定をすべて外すと、一覧から消える。

### 8.4 設定画面

- データフォルダ、出力先 (どちらもローカル設定。§4.2)
- プロジェクトの一覧 (コード、名前、開始日、期限。CSV から取り込み)
- 出力と出力セットの管理 (テンプレートの編集を含む)
- メモ欄の定義 (日次画面からも変更できる)
- 長さの表記 (§6)

ヘッダーの歯車のボタンから、大きなダイアログで開く。左に項目を縦に並べ、選んだ項目の中身を右に出す。

- 変更は、項目ごとの「保存」でまとめて書く。プロジェクトの一覧のように、何か所か直してから書くものがあるため。
- 入力の誤りで保存できなかったときは、その誤りを「保存」の横に出す。表の中の誤りは行が多いと見つけにくく、押したボタンの近くなら見落とさないため。
- 行を足す、消す、並べ替える表 (プロジェクト、メモ欄の定義、CSV の列、出力セットに入れる出力) は、同じ形にする。枠で囲み、左端に並べ替えの取っ手、右端に消すボタンをいつも出し、行を足すボタンは表の下端に置く。行が多いときは、見出しと下端を残して行だけを送る。
- 保存していない変更があるまま、ほかの項目へ移ろうとしたときと閉じようとしたときは、破棄してよいかを確かめる。破棄すると、その項目は保存した値に戻る。保存を押さずに移ると、変更が残っていることに気付けないため。
- 保存するときは、settings.yaml のうち、その項目の部分だけを開いたときと比べる。他で変わっていたら、保存せずに読み直して知らせる (§4.3)。ほかの項目の変更は、書いたものも書いていないものもそのまま残す。
- データフォルダ、出力先、長さの表記には、欄の名前の下に、何に使うものかを短く書く。普段は開かない画面で、何を変える欄なのかを思い出せるようにするため。
- データフォルダ、出力先、長さの表記には「初期値に戻す」を置く。欄に初期値 (§4.2、§4.4) を入れるだけで、書くのは「保存」。もう初期値のときは押せない。フォルダは、書き方 (Windows の短い名前、大文字と小文字など) が違っても、同じフォルダなら初期値とみなす。
- データフォルダと出力先は、OS のフォルダを選ぶダイアログで選ぶ。
- データフォルダは、ないフォルダを選ぶと保存できない。初期値だけは、なくても保存できる。初めて起動したときと同じく、空のデータから始めるもののため。
- データフォルダを変えても、ファイルを移したりコピーしたりしない。1 台目の PC ではフォルダを OneDrive などへ移してから指し直し、2 台目からは同じフォルダを指す。保存したら、新しいデータフォルダから読み直す。
- 長さの表記は、入力中に、いくつかの長さをその書式で書いた結果を出す。

プロジェクトは、CSV から取り込める。

- CSV は UTF-8 で読む。
- 1 行目を見出しとして飛ばすかを選ぶ。
- コード (必須)、名前、開始日、期限に当てる列を、それぞれ選ぶ。
- 今の一覧に足すか、一覧ごと置き換えるかを選ぶ。足すときは、同じコードの名前、開始日、期限を CSV の値で置き換える。
- CSV の中に同じコードが何行かあれば、後の行を使う。
- 開始日と期限の列は、日付の書式 (§6.2) で読み方を指定する。2 つの列は同じ書式で読む。`yyyy-MM-dd`、`yyyy/MM/dd`、`MM/dd/yyyy` などの候補から選ぶか、記号で書く。国によって月と日の並びが違うので、推し量らずに指定してもらう。
- 日付は、書式で書いたときと同じ形だけを読む。`MM` は必ず 2 桁、`M` は先頭に 0 を付けない 1〜2 桁。`yy` は 2000 年代とする。曜日 (`EEE`、`EEEE`) は読めないので、書式に入れたらエラーにする。
- 開始日や期限が空の行は、それがないものにする。コードが空の行、日付が書式で読めない行 (ない日付を含む)、開始日が期限より後の行があれば、何も取り込まず、何行目のどの値が読めないかを知らせる。直してから取り込み直すため。
- 取り込んだ結果は一覧の編集に入るだけで、「保存」で書く。書く前に確かめられるようにするため。

プロジェクトの一覧は、表で直す。

- 1 行が 1 件で、コード、名前、開始日、期限を直接直せる。行を足す、消す、ドラッグで並べ替えることができる。並べた順が settings.yaml の並びになる。
- 期限が今日より前のプロジェクトは、終わってもう使わないものなので、ふだんは隠す。「期限切れを表示する」で、一覧の末尾にまとめて出す。末尾に出すのは画面だけで、settings.yaml の並びは変えない。
- どれを隠すかは、一覧を読んだときに決める。直している途中で期限を変えても、行は動かさない。入力中の行が消えないようにするため。
- 並べ替えは、出している行どうしで入れ替える。隠している行は、元の位置のままにする。期限切れとそうでない行は、それぞれの中で並べ替える。隠した行や、もう一方の組の行と位置が入れ替わると、出したときに思わぬ位置に動いて見えるため。
- 保存するときに、コードが空の行、同じコードの行、開始日が期限より後の行があれば、保存しない (§4.4 と同じ決まり)。

メモ欄の定義は、表で直す。日次画面の鉛筆のボタン (§8.1) からも、同じものを開く。

- 1 行が 1 つの欄で、名前、型 (テキストか真偽値)、前回の値を引き継ぐかを直せる。行を足す、消す、ドラッグで並べ替えることができる。並びが日次画面の順になる。
- 保存するときに、名前が空の行、同じ名前の行があれば、保存しない (§4.4 と同じ決まり)。名前の前後の空白は除く。

出力と出力セット (§7.1) は、左に一覧、右に選んだものの中身を出して直す。

- 一覧は、出力セット、出力の順に、それぞれファイル名の順で並べる。読めないファイルは、末尾にファイル名で並べる。保存していない変更があるものは、名前の前に印を付ける。一覧の上に「既定の出力」(`default_output`) を選ぶ欄を置く。出力セットと出力のどちらも選べる。選んだ時点で書く。
- 新しく作るときは、テキスト、CSV、出力セットから選ぶ。出力が 1 つもないときは、出力セットは選べない。
- 出力 (テキストか表) と出力セットを新しく作れる。新しいものは、そのまま保存できる中身で始める。
- 中身は 1 つずつ「保存」で書く。保存していない変更は、一覧で別のものを選んでも残す。閉じるときの確かめは、ほかの項目と同じ。
- 出力の設定 (ファイル名の書式、テキストなら拡張子、文字コード、改行、CSV なら見出しの行、行の単位、計上する時間のない行を出さないか) は、それぞれの欄で直す。テキストの本文は等幅の入力欄で直す。
- CSV の列は、見出しと値の表で直す。列は足す、消す、並べ替えることができる。値はテンプレートを書かずに一覧から選ぶ。日付と時間は書式も選ぶ。一覧にない値は「自由に書く」でテンプレートを書く。ファイルには、選んだ値もテンプレートとして書く (§7.3 の形のまま)。

| 値 | 行の単位 | 書くテンプレート |
| --- | --- | --- |
| 日付 (書式) | どちらも | `{{date "書式"}}` |
| コード | プロジェクト / 記録 | `{{.code}}` / `{{.project.code}}` |
| プロジェクト名 | プロジェクト / 記録 | `{{.name}}` / `{{.project.name}}` |
| タスク名 | 記録 | `{{.title}}` |
| 時間 (書式) | どちらも | `{{duration .minutes "書式"}}` |
| 分 | どちらも | `{{.minutes}}` |
| タグ | 記録 | `{{join .tags " "}}` |
| メモ | 記録 | `{{.note}}` |

- ファイルの列の値が上のどれかと同じ形なら、その値として出す。違えば「自由に書く」として出す。行の単位を変えたときは、両方にある値 (コード、プロジェクト名など) を新しい単位の形に書き直す。
- 出力セットは、入れる出力を選んで並べる。並びが日次画面のタブの順になる。
- 出力を直しているあいだは、保存する前の中身で、開いている日の結果を中身の下に出す。作れないときは、誤りをそこに出す。
- 誤りのある中身 (テンプレートの書き間違い、必須の項目がないなど) は保存しない。templates/ に読めないファイルを作らないため。
- 画面から保存すると、ファイルは書き直すので、手で書いたコメントは残らない。
- 名前を変えたら、ファイル名も変える。出力の名前を変えたら、その出力を入れている出力セットの中の名前も書き換える。出力や出力セットの名前を変えたら、既定の出力も追いかける。出力セットが出力を名前で指しているので、そのままだと指す先がなくなるため。
- 名前は、出力と出力セットを通して重ならないようにする (§7.1)。ファイル名に使えない文字 (`/\:*?"<>|`) は入れられない。
- 消すときは確かめる。出力セットに入っている出力は消せない (どのセットに入っているかを知らせる)。既定の出力を消したら、既定はなくなる。
- 保存と削除の前に、そのファイルが開いたときから他で変わっていないかを比べる。変わっていたら、書かずに読み直して知らせる (§4.3)。
- 読めないファイル (§7.1) は、一覧に理由と一緒に出し、消すことだけできる。直すときは、ファイルを手で直す。

## 9. MCP

アプリと同じ実行ファイルを `lumetio mcp` で起動すると、画面を出さずに MCP サーバ (stdio) として動く。CLI は作らない。

AI が 1 回の依頼をなるべく少ない呼び出しで済ませられるように、まとめて扱えるものはまとめる。
画面の記録の行と左ペインでできることを、同じ決まりで行う。

| ツール | 中身 |
| --- | --- |
| `list_tasks` | 直近のタスク (最後に記録した日を含む)、よく使うタスク、定期的なタスクを返す。各タスクのプロジェクト、タグ、計上しない、いつもの時間を含む |
| `list_projects` | その日に使えるプロジェクト (期間の中のもの) を返す |
| `get_days` | 期間の各日の記録、予定、スキップ、メモ欄 (定義の型を含む)、プロジェクトごとの合計を返す。期間は最大 31 日。省略すると今日 1 日 |
| `add_records` | 記録をまとめて足す。1 つでも誤りがあれば、何も書かない。足し方は画面の＋と同じ (§5.2) |
| `update_record` | 記録の時間 (並びごと置き換える)、プロジェクト、タグ、メモ、計上しない、完了を直す |
| `remove_record` | 記録を消す |
| `skip_plans` | 予定をまとめてスキップする (§5.3) |
| `set_notes` | メモ欄をまとめて書く (§5.5) |
| `render_output` | 出力または出力セットの中身を返す。名前を省略すると既定の出力 |
| `export_output_set` | 出力セットか出力 1 つを出力先に書く (§7.4)。名前を省略すると既定の出力 |

- 日付は `YYYY-MM-DD` で渡し、省略すると今日。
  入力は §6 などのルールで検証してから書き込み、入力の誤りはツールのエラーとして返す。
- 記録は、その日のタスク名で指す (§5.1 で、1 日の中でタスク名は重ならない)。
- `add_records` で、その日にもう記録のあるタスクを足すときは、時間だけを足す (§5.2)。
  プロジェクト、タグ、メモ、計上しないに、すでにある記録と違う値を指定したら、何も書かずにエラーにする。
  違う値を黙って捨てると、AI が変わったと思い込むため。
- 予定を実施済にするツールは持たない。
  予定と同じ名前のタスクを `add_records` で足すと、予定は消えて記録になる (§5.3)。
  時間を省略すればいつもの時間で入り、指定すればその時間で入る。
- 完了は、`update_record` で、そのタスクを最後に記録した日の記録に `done: true` を付ける (§5.2)。
  その日より後に同じタスクの記録があれば、完了の印が効かないので、エラーにして最後に記録した日を返す。
- `set_notes` で書けるのは、settings.yaml に定義のある欄だけ。
  定義にない名前は、何も書かずにエラーにし、書ける欄の名前と型を返す。
  AI が書き間違えた名前で、その日にだけある欄を作らないため。
  値が欄の型に合わないときもエラーにする。
- `export_output_set` はダイアログを出せないので、すでにファイルがあるときの扱いを引数 `on_conflict` で選ぶ (`overwrite` で上書き、`rename` で別名)。
  省略するか `ask` なら、すでにファイルがあるとき、何も書かずに、あるファイルを並べたエラーを返す。
- 期間の外のプロジェクト (§4.4) があれば、結果と一緒に警告を返す。
  警告があっても、出力は止めない。
- 読めなかった日次ファイルなど、計算から除いたものがあれば、結果と一緒に知らせる。
- GUI や他の PC と同時にファイルを書いて衝突したら (§4.3)、何も書かずにエラーを返す。
  AI は読み直してから呼び直す。
- タスクの設定 (よく使う、いつもの時間、繰り返し) と、settings.yaml の内容は、MCP からは変えない。
  繰り返しの組み合わせなどは、画面で確かめながら設定するほうが確実なため。

## 10. 品質

- Go: gofmt、go vet、ドメイン (時間の解釈、繰り返しの判定、工数の計算、出力の生成) は単体テストを書く。
- フロントエンド: 整形と静的解析は Biome (1 つで両方を行い、設定も 1 つで済むため)。
- フロントエンドのテストは Vitest。関数は Node で動かし、画面の部品は browser mode で Chromium と WebKit の両方で動かす。Windows の WebView2 は Chromium 系、macOS の WKWebView は WebKit なので、どちらの OS の画面の不具合も拾うため。
- バグを直したら、再現するテストを足す。
